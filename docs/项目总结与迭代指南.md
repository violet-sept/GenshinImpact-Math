## 1. 一页纸：这是什么

用**可拖拽的交互式动画**讲离散数学。核心主张不是"把教材搬上网页"，而是：

- 每个知识点固定五步：`① 看一看 → ② 玩一玩 → ③ 起个名 → ④ 练一练 → ⑤ 换个场景`
- **不操作不能推进**（未完成时"下一步"是禁用的，并给温和说明而非报错）
- 面向**零基础**用户，"傻子也能看懂"是硬指标，不是修辞
- 响应式多端（手机到投影仪）、可纯键盘操作、尊重减少动画偏好

## 3. 环境与已知陷阱（先读这节，能省你半小时）

### 3.1 当前这台机器是一个**受限沙箱**

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| `npm install` 报 `EPERM ... _cacache\tmp` | npm 默认缓存目录在工作区之外，不可写 | 把缓存指到工作区内：`npm install --cache ./.npmcache` |
| `vite build` 报 `EPERM spawn EPERM` | 沙箱禁止 Node 用管道 stdio 捕获子进程输出；Vite 在 Windows 上会跑 `net use` 探测网络盘（`optimizeSafeRealPathSync`） | 用 `npm run build:shim` / `npm run dev:shim`（`node --require ./scripts/exec-shim.cjs`）|
| Vitest 报 `Failed to start forks worker ... spawn EPERM` | 同上，forks 池需要管道 | `vitest.config.ts` 里已固定 `pool: 'threads'`，**不要改成 forks** |
| Vitest 报 Tailwind oxide "stream did not contain valid UTF-8" | `vitest.config.ts` 加载了带 Tailwind 插件的 vite 配置，触发了原生二进制加载 | **故意**让 `vitest.config.ts` 不带任何 plugin，**不要"统一"两个配置文件** |
| `--reporter=basic` 启动即崩 | **Vitest 5 已移除**该 reporter，会尝试当自定义模块加载并失败 | 用默认 reporter，别加这个参数 |
| 统计代码行数得到**偏小**的数字 | `Measure-Object -Line` **不统计空行**；本机 `Get-Content` 对 LF-only 文件还会少算（同一文件返回 450，实际 596 行）| 行数一律用 `node` 按 `\n` 切分统计 —— **本文所有行数均以此为准**（曾因此把 27,060 行误报成 24,131 行）|

**这些都是沙箱/工具版本特性，不是本项目代码的 bug。** 在正常开发机上 `npm run dev` / `npm run build` 直接可用，垫片可以不要。

### 3.3 本地启动与打开（启动器）

**日常打开就一件事：双击 `discrete-lab\start-site.cmd`。**

它按顺序做四件事：`dist/` 不存在则先构建 → 起预览服务 → **轮询等端口真的返回 200** → 打开浏览器。
最后一步刻意用轮询而不是固定 sleep，避免"浏览器比服务器先就绪"导致的首屏白页。
停止服务 = 关掉那个最小化的 `Discrete Lab server` 窗口（服务跑在那个窗口里，关窗即停）。

三种入口的分工：

| 场景 | 命令 | 地址 |
| --- | --- | --- |
| 只想看成品 | 双击 `start-site.cmd` | http://localhost:4173/ |
| 改代码（热更新） | `npm run dev` | http://localhost:5173/ |
| 只起预览服务 | `npm run preview:shim` | http://localhost:4173/ |

`package.json` 里为此补了 `preview:shim`（`--strictPort`），与 `dev:shim` / `build:shim` 同一套路。
**`--strictPort` 意味着 4173 被占用时它会直接失败**，而不是偷偷换端口 —— 这是有意的，
否则用户会对着一个"启动了但地址不对"的窗口发呆。启动前先确认没有别的进程占着 4173。

#### ⚠️ 陷阱 A：不要双击 `dist\index.html`

会得到**一片空白页**。`file://` 协议下浏览器把本地文件视作不透明源，
`<script type="module">` 会被 CORS 直接拦掉。**必须经 http 服务器访问。**

注意区分：`vite.config.ts` 里的 `base: './'` 相对路径解决的是**子目录部署**问题，**不是** `file://` 直开问题。
两者常被混淆，改配置时别搞错因果。

#### ⚠️ 陷阱 B：`.cmd` 必须保持纯 ASCII

实测踩过这个坑：第一版启动器写了中文提示，**直接崩**。
原因是 `cmd.exe` 按系统码页（这里 GBK/936）**逐行读取**批处理文件，而文件内容是 UTF-8，
中文字节被错误切分后把命令行撕碎 —— 日志里 `start` 被啃成 `tart`、其后的参数变成 `'tch{}'`，
末尾 `'��止服务：…' is not recognized`。

**改完这个文件必须验证非 ASCII 字节数为 0：**

```powershell
$b = [System.IO.File]::ReadAllBytes("discrete-lab\start-site.cmd")
($b | Where-Object { $_ -gt 127 }).Count   # 必须是 0
```

（`chcp 65001` 救不了这个 —— 文件在被读取时就已经解析错了。想要中文提示就得用 GBK 存盘，
但那会把启动器绑死在中文 Windows 上；提示文字本身无关紧要，**ASCII 是这里唯一稳妥的选择**。）

#### 验证状态（诚实说明）

**已验证**：启动器实测跑通 —— 构建检查 → 起服务 → HTTP 200 → 打开浏览器，退出码 0。

**未验证**：**"启动器自己的窗口退出后，服务器是否继续存活"**。
原因是我的工具调用结束时会把所有子进程一并回收，所以在我这里一测就是「进程没了」，
这属于工具行为，无法用来判断启动器的真实表现。
从资源管理器双击时那个最小化窗口是独立进程，按 Windows 语义应当持续存活，
**但这一条没有实测背书，不要当成已验证结论。**

若出现"浏览器打开了、随后页面失去连接"，改用 `start /b` 让它脱钩父进程，
或注册成计划任务 —— 不要靠反复重试。

## 4. 架构与不可破坏的约定

### 4.1 分层

```
内容层   topics/impl/*.tsx        每个知识点的五步脚本与交互（21 个文件）
编排层   learn/TopicPage.tsx      步骤机 + 三级提示 + 进度 + 键盘导航
原语层   primitives/              Venn / GraphView / MatrixGrid / TruthTableView
内核层   kernels/                 纯函数算法，100% 可测
平台层   platform/                响应式 / 输入 / 无障碍 / 持久化
```

### 4.2 数据流

```
catalog.ts (轻量元数据)  ──► Home / KnowledgeMap / ModulePage 同步引用
        │
        └─ isReady(id)? ──► loader.ts (import.meta.glob 自动发现) ──► impl/<ID>.tsx
                                                                        │
                              TopicPage 运行器 ◄── Topic { stages: [5], hints: [3] }
                                    │
                     ctx { solved, hintLevel, solve, say, announce, reducedMotion }
                                    │
                            impl 内 useSolveOnce(ctx, 条件) ──► progress.solveStage()
```

### 4.3 三条铁律（改了就会坏）

**铁律一 · 内核层零 React 依赖**
`src/kernels/` 里不能 `import` 任何 React。收益是三个具体的：
① 能穷举单测验证数学正确性（教学产品最不能容忍教错）；
② 同一份算法既驱动动画又被沙盒页复用（`SandboxPage` 就是这么用的）；
③ 未来可复用到题库/CLI。

**铁律二 · 算法返回「步骤序列」而非「最终答案」**

```ts
export function dijkstra(g: Graph, start: string): Step<DijkstraState>[]
```

因为每帧状态都已算好，`next / prev / goTo` 全是纯索引移动 ——
**暂停、回退、单步、时间旅行、拖时间轴全部免费**。这是交互式动画相对一段视频的全部价值。
**新增算法必须遵守这个签名形状**，否则 `useStepper` 无法消费它。

**铁律三 · 不操作不能推进**
`StageSpec.requireSolve` 默认 `true`；内容契约测试强制**每个知识点至少 3 个步骤**带真实交互。
完成判定统一走 `useSolveOnce(ctx, when)`，它保证条件成立只触发一次、条件不再成立时自动解除
—— 直接写 `useEffect(() => { if (ok) ctx.solve() })` 会造成无限循环。

### 4.4 内容契约测试是唯一的质量防线

`src/topics/content.test.tsx` 把规划书 §3.2 的**写作规范变成了会失败的 CI 断言**：
SSR 渲染每个知识点的全部 5 步（捕捉运行时报错）、校验旁白非空 / 提示恰好 3 条 /
≥3 步带闸门 / ≥2 条误解 / ≥4 条术语且都有大白话 / **文案不含劝退词**。

反面词清单：`['显然','易证','由定义立得','众所周知','不言而喻','不证自明']`

> ⚠️ **维护约定**：清单里**刻意不收单字词**（原先收了 `略`，结果 `忽略孤立点` 被误判）。
> 中文没有词边界，**宁可少收几个，也不要制造假阳性让规则失去信任**。加词时请附带验证。

## 5. 精确接口契约（改代码前必读）

### 5.1 知识点契约 `src/topics/types.ts`

```ts
type StageKind = 'hook' | 'explore' | 'name' | 'practice' | 'transfer'   // 顺序固定

interface StageCtx {
  solved: boolean
  hintLevel: 0 | 1 | 2 | 3
  solve: () => void                    // 调用即通关
  say: (text: string, tone?: 'normal'|'reject'|'accept') => void   // 覆盖旁白条
  announce: (text: string) => void     // 读屏播报
  reducedMotion: boolean
}

interface StageSpec {
  label?: string                       // 覆盖默认步骤名
  short?: string
  narration: string                    // 静态人话旁白
  requireSolve?: boolean               // 默认 true；只有纯展示的钩子才设 false
  hints: [string, string, string]      // 元组！恰好 3 条：H1 方向 / H2 指路 / H3 完整答案
  render: (ctx: StageCtx) => ReactNode
}

interface Topic {
  id, title, moduleId, oneLiner, outcome, prerequisites
  bigIdea: string
  misconceptions: Misconception[]      // ≥2 条
  formalDefinition: ReactNode
  glossary: GlossaryEntry[]            // ≥4 条，每条必须有 plain
  stages: [StageSpec ×5]               // 元组！恰好 5 项
}
```

**`stages` 与 `hints` 是元组类型**：少一项是编译错误，这是故意的。

## 6. 操作手册（Playbook）

### 6.1 验证三连（每次改完必跑）

```bash
cd discrete-lab

# 1) 类型
npm run typecheck

# 2) 测试（沙箱里必须带 shim，且不要加 --reporter=basic）
node --require ./scripts/exec-shim.cjs ./node_modules/vitest/vitest.mjs run

# 3) 构建
npm run build:shim
```

**基线**：`211 passed` / `tsc` 静默 / 构建成功。任何偏离都要先解释清楚再继续。

### 6.2 新增一个知识点

1. 在 `src/topics/catalog.ts` 的 `CATALOG` 里加一条元数据（`id/title/moduleId/oneLiner/hookTeaser/prerequisites/difficulty/minutes`）。
2. 在 `src/topics/impl/<ID>.tsx` 里 `export default` 一个 `Topic`。

**不需要改任何注册表** —— `loader.ts` 用 `import.meta.glob('./impl/*.tsx')` 自动发现，
Vite 自动切独立 chunk。这是刻意的设计，避免多人协作时的注册表合并冲突。

最小骨架见 `../README.md` 的"怎么新增一个知识点"一节。

**验收**：跑测试；148 项会变成 `(N+1)×7 + 1`，自动覆盖你新加的知识点。

### 6.3 新增一个算法内核

1. 放进 `src/kernels/`，**不要 import React**。
2. 若要驱动动画，返回 `Step<S>[]`（`{ state, note? }` 形状见 `kernels/types.ts`）。
3. **在 `kernels.test.ts` 里加交叉验证**，不是"跑一遍看没报错"。

本项目的测试标准是**与独立实现比对**，参考已有做法：

| 被测 | 交叉验证方式 |
| --- | --- |
| 欧拉判定 | 枚举 4 点 5 边图的全部 31 个子图，与穷举所有走法的暴力搜索逐一比对 |
| Dijkstra | 与"枚举所有简单路径取最小"比对 + settled 不变量 |
| 路径还原 | 还原路径权重必须严格等于 `dist` |
| Kruskal | 与"枚举所有 n−1 边组合取最小连通"比对 |
| 传递闭包 | 与 Warshall 比对 + 最小性（去掉任一新边就不再传递）|
| 排列组合 | 与暴力枚举比对（n ≤ 10）+ 帕斯卡递推 |
| 汉诺塔 | 真实模拟每步，验证大盘不压小盘且步数 = 2ⁿ−1 |

> **为什么值得这么较真**：一根画错的边、一个错误的松弛顺序，会让学生形成**错误认知**，
> 代价远高于一次崩溃。崩溃用户会重试，学错了用户不会。

### 6.4 修改某个知识点的文案

只改 `narration` / `hints` / `glossary[].plain` 这类字符串时：
跑测试即可，新增的劝退词会被自动拦下。

### 6.5 改设计令牌 / 主题

令牌定义在 `src/index.css`（Tailwind 4 的 `@theme` / `@custom-variant`）。
语义色有配套的 `-50/-500/-700` 梯度，`Chip` 依赖它们做形状冗余。

⚠️ **改主题时注意**：`index.html` 里有一段**首屏防闪烁内联脚本**，
它读 `localStorage['dl.settings.v1']` 并预先应用 `dark` / `contrast-high` / `motion-off` / `--dl-font-scale`。
**新增任何影响首屏外观的设置项，都必须同步更新这段内联脚本**，否则会出现主题闪变（见 §8 缺陷 2）。

### 6.6 新增页面

1. 在 `src/pages/` 加组件，2. 在 `App.tsx` 里 `lazy()` 引入并注册 `<Route>`，
3. 若要进导航，改 `src/layout/AppShell.tsx`（桌面导航 + 移动端底部标签栏两处）。

## 8. 待修正缺陷与文档偏差

以下是我在写这份文档时**实际核对出来的问题**，按严重度排列。

### ~~缺陷 1 · 没有版本控制~~ ✅ 已修复

见 §3.2 与 §13。仓库已有 git：`main` 分支 + GitHub Actions 门禁 + Pages 部署，
回滚能力具备。**但有了 git 不等于有了纪律** —— 做大范围重构前先确认 `git status` 干净，
一次提交只做一件事。

### 缺陷 2 · 首屏内联脚本漏了「课堂模式」

`index.html` 的防闪烁脚本应用了 `dark` / `contrast-high` / `motion-off` / `--dl-font-scale`，
但**没有** `classroom` 类，也没有乘上课堂模式的 1.25 倍字号：

```js
// index.html（现状）—— 缺少 classroom 处理
if (t.fontScale) el.style.setProperty('--dl-font-scale', String(t.fontScale))
```

而 `settings.tsx` 实际是 `fontScale * (classroom ? 1.25 : 1)` 且会 toggle `classroom` 类。

**后果**：开启课堂模式后，首屏会以正常字号渲染一瞬，随后 React 挂载才跳变成放大字号
（即"防闪烁脚本"自己制造了一次闪烁）。**课堂模式本来的使用场景就是投屏**，这个场景下最容易被看到。

**修法**（一行）：在内联脚本里补 `if (t.classroom) { el.classList.add('classroom'); scale *= 1.25 }`。

### 缺陷 3 · 根本未实现的知识点缺少内核

`S3` `R3` `R4` 三个未实现知识点，**内核其实已经写好了**：

| 待实现 | 已有内核 |
| --- | --- |
| `S3` 幂集与笛卡尔积 | ✅ `powerSet`、`cartesian` |
| `R3` 关系的闭包 | ✅ `reflexiveClosure`、`symmetricClosure`、`transitiveClosureSteps` |
| `R4` 等价关系与划分 | ✅ `isEquivalence`、`equivalenceClasses` |
| `L4` 推理规则与证明 | ❌ **无内核** —— `logic.ts` 里没有任何推理规则 / 证明步骤函数，需要从零写 |

也就是说：**S3/R3/R4 只差交互层**（`ComingSoon` 组件里那句"算法内核和单测已经就位"对这三个是真的），
**L4 是真正需要从内核开始做的一条**。而且这三个知识点**没有对应的内核单测**覆盖 —— 
所以"内核已就位"这句话目前只在类型层面成立，没有测试背书。

### ~~缺陷 4 · 文档与实测数字不符（README 漂移）~~ ✅ 已修复

README 已按实测数字重写，下列偏差全部消除：

| 原先 README 写的 | 现在写的（实测） |
| --- | --- |
| 目录树注释「`catalog.ts` **27 个**知识点」 | **25 个**（`MODULES` 9 个是对的）|

### 缺陷 5 · 渲染层完全没有自动化测试覆盖

内容契约测试只做 **SSR 渲染**（验证"不抛异常 + 结构完整"），
**不覆盖任何交互行为**：点下去会发生什么、拖拽是否生效、闸门是否真的拦住、
`useSolveOnce` 是否正确触发，目前全靠源码级人工核对。

规划书 §11.1 要求的 Playwright 多视口矩阵**没有做**。

### 缺陷 6 · 无障碍只有人工走查

键盘通路是原语内建的（`useSvgDrag`），设计上到位，但：
- **未跑 axe-core 自动化扫描**
- **未经真实读屏软件用户验证**
- 色彩对比度未做过量化校验（只做了"配色时注意了"）

### 缺陷 7 · 子代理在开发中修正过真实数据错误（需复核）

开发期间发现并修正了两处**我方原始设计里的数学数据错误**：
柯尼斯堡七桥的桥分布（原设计算出来度数不是全奇数 —— 应为 A–C×2, B–C×2, C–D, D–A, D–B，
度数 3/3/5/3、四个奇点）、以及 `G1` 迁移图的度序列。
修正后由脚本复核，但这提示：**内容里的具体数字比算法更容易出错**，且**没有测试在保护它们**。

## 11. 不要做的事（反面清单）

- ❌ **不要**让 `kernels/` 依赖 React（铁律一）
- ❌ **不要**让新算法只返回最终答案（铁律二）
- ❌ **不要**用裸 `useEffect` 调 `ctx.solve()`，必须走 `useSolveOnce`（铁律三 / 无限循环）
- ❌ **不要**把 `requireSolve` 设成 `false` 来"让流程更顺"（内容契约要求 ≥3 步带闸门）
- ❌ **不要**在面向用户的文案里写「显然」「易证」「由定义立得」「众所周知」
- ❌ **不要**用纯红色表示错误（用橙色 `#F97316`，降低焦虑 + 兼顾色觉障碍）
- ❌ **不要**用 `<Math>`（遮蔽全局对象），用 `<Formula>`
- ❌ **不要**用只有颜色没有形状/文字冗余的语义提示（`Chip` 已内建 `●▲✓!◆○`）
- ❌ **不要**把 `vitest.config.ts` 和 `vite.config.ts` "统一"（会触发 Tailwind oxide 原生模块加载失败）
- ❌ **不要**把 Vitest 的 `pool` 改回 `forks`（沙箱 `spawn EPERM`）
- ❌ **不要**为了"省事"让知识点跳过 `catalog.ts` 注册（首页 / 地图 / 术语表都会漏掉它）
- ❌ **不要**在没有 git 基线的情况下做大范围重构（现在已有 git，但动手前仍要先确认 `git status` 干净）
- ❌ **不要**把 `public/wallpaper/*.mp4` 加进 git（超过 GitHub 单文件 100MB 上限，push 会被整个拒掉）
- ❌ **不要**在没配 `VITE_WALLPAPER_URL` 的构建里强行让 `wallpaper-on` 生效（毛玻璃会压在空白上，正文对比度不达标）
- ❌ **不要**在 `start-site.cmd` 里写非 ASCII 字符（GBK 码页会把命令撕碎，实测崩过，见 §3.3）
- ❌ **不要**让用户直接双击 `dist/index.html`（`file://` 下模块脚本被 CORS 拦，必然白屏）
- ❌ **不要**去掉 `preview:shim` 的 `--strictPort`（占用时静默换端口会让人对着错地址排查）

## 13. 本次整理（仓库化与开源准备）

一次性的仓库整理，目的是让项目**既能开源到 GitHub，也能直接用 GitHub Pages 部署**。
以下都是实测过的，不是计划。

### 13.1 目录形状变了：仓库根 = 本项目目录

整理前，项目裹在一个**更大的上层工作区**里，
旁边堆着素材池（`原神表情包/`、`草神壁纸/`）、运行时缓存（`.npmcache/`、`.corepack/`）
和散落的原始 PNG。**这些都不该进仓库**，所以把仓库根定在 `discrete-lab/`
（GitHub 上叫 `violet-sept/GenshinImpact-Math`），
并把它真正需要的东西收了进来：

| 动作 | 从 | 到 |
| --- | --- | --- |
| 移入 | `../docs/离散数学交互式动画教学网站-项目规划书.md` | `docs/` |
| 移入 | `../tools/pick-big-idea-stickers.ps1` | `tools/` |
| 移入 | `../summary.md`（本文） | `docs/项目总结与迭代指南.md` |
| 合并 | 工作区根 `README.md` 的「这个站在做什么」「六条铁律」 | 并进仓库 `README.md` |
| 留在外面 | 素材池、缓存、原始 PNG、`start-site` 之外的工作区杂物 | **不进仓库** |

工作区根的 `README.md` 改成了一张「这块盘上都有什么」的索引，避免和仓库 README 两份内容互相漂移。

### 13.3 壁纸视频：从「仓库里 135MB」改成「可选外链」

这是本次唯一一处**代码行为变化**，原因见 `README.md` 的「关于动态壁纸」一节。

- `public/wallpaper/nahida.mp4`（141,533,616 字节，sha256 `50c0548…a22019`）**不进仓库**，`.gitignore` 挡掉；
  **它现在住在哪：本仓库 v1.0 Release 的附件** ——
  `https://github.com/violet-sept/GenshinImpact-Math/releases/download/v1.0/nahida.mp4`
  （已核对 sha256 与本地那份完全一致）。`deploy.yml` 把这个地址写成默认值，
  所以线上站开箱就有壁纸，不需要配任何变量。
- `src/platform/settings.tsx` 新增 `HAS_WALLPAPER` / `WALLPAPER_SRC`：
  - 开发模式 → 用本地文件（`public/wallpaper/nahida.mp4`），离线可用；
  - 生产构建 → 用 `VITE_WALLPAPER_URL`，没配就**不渲染壁纸层**；
- `DynamicWallpaper.tsx` 给 `<video>` 挂了 `onError`，外链失效时通知 settings 把整层收掉，
  避免「毛玻璃压在空白上」；
- 「显示设置」里的动态壁纸开关在没有视频时**整组不渲染**；
- `vite.config.ts` 加了 `dl-wallpaper-flag` 插件，把同一个布尔值注入 `index.html` 的首屏脚本。

⚠️ **这个布尔值有两处消费者**（`index.html` 内联脚本 + `settings.tsx`），规则必须一致。
两边都用 `mode === 'development'` 判定，**刻意不用 `import.meta.env.DEV`** ——
那个取自 `NODE_ENV`，将来加自定义 mode 时会与配置里的 `mode` 分叉。

**实测验证**：无外链构建 `hasWallpaper=false`、`wallpaperOn` 被折叠成 `!1`、设置项被 tree-shake 掉；
有外链构建 `hasWallpaper=true` 且 bundle 里是外链地址；dev server `hasWallpaper=true` 且本地视频
HTTP 200 / `video/mp4` / 字节数一致。

### 13.4 门禁与部署（实测）

```bash
npm run typecheck        # 0 报错
npm test                 # 211 passed / 211
npm run build            # 成功，dist/ 约 1.9MB
```

`base: './'` + HashRouter 的组合让 Pages 部署**不需要**改 base、不需要 404 重写、不需要 `gh-pages` 分支。
工作流里也跑了测试：宁可发布失败，也不要发一个白屏站点上去。

### 13.5 本次**没有**做的事

- **没修缺陷 2**（首屏内联脚本漏了 `classroom`）—— 那是功能问题，不属于「整理文件」的范围，仍在 §8。
- **没做真人可用性测试**，没加 E2E / 视觉回归 / axe-core。
- **没有压缩壁纸视频**：这个环境里没有 ffmpeg，无法转码。想压得在本机做。
- **没有配 CI 缓存之外的任何 CDN / 备案相关设置**（规划书里提过，但不在本次范围）。
