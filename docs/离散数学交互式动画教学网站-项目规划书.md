## 1. 项目背景与目标

### 1.1 问题陈述

离散数学是计算机、软件工程、信息安全、数学等专业的核心基础课，但它有三个"劝退特性"：

| 痛点 | 具体表现 | 传统教材/视频为何解决不了 |
| --- | --- | --- |
| **抽象不可见** | 集合、关系、图、映射、自动机都是"结构"，学生看不见结构长什么样 | 静态纸面只能用一张图"定格"，看不到构造过程 |
| **符号密度高** | ∀ε>0、R 的传递闭包、同态映射…… 符号一多，认知负荷爆表 | 视频是线性播放，学生跟不上就只能倒回去重看 |
| **只会背不会用** | 会背欧拉公式，但给一张图判断是否有欧拉回路就懵 | 缺少"自己动手试错—立刻看到反馈"的闭环 |

结果是：**大部分人靠刷题和背定义通过考试，考完即忘**，更谈不上建立"结构思维"。

### 1.2 项目愿景

> 让任何一个愿意学的普通人，坐在手机或电脑前，用 10 分钟通过"拖动、点击、试错"真正理解一个离散数学概念，而不是记住一个定义。

### 1.3 目标拆解（可衡量）

**北极星指标（North Star Metric）**
> 单个知识点的**"无提示自主通关率"**：用户在完全没有教师讲解、不点开"答案"的情况下，独立完成该知识点全部交互环节的比例。目标 ≥ 60%。

**支撑目标**

| 维度 | 指标 | 目标值 |
| --- | --- | --- |
| 理解 | 知识点后测正确率 | ≥ 75% |
| 体验 | 单知识点中位完成时长 | ≤ 8 分钟 |
| 体验 | 首次交互成功率（第一个交互环节一次做对） | ≥ 70% |
| 留存 | 完成 1 个知识点后继续下一个的比例 | ≥ 40% |
| 性能 | 移动端首屏可交互时间（4G 中端安卓） | ≤ 2.5s |
| 性能 | 动画帧率（中端设备） | 稳定 ≥ 50fps |
| 无障碍 | 全站键盘可完成核心流程 / WCAG 2.1 AA | 100% |

### 1.4 非目标（明确不做，防止范围蔓延）

- ❌ 不做题库/刷题平台（不与考试系统竞争）
- ❌ 不做视频课程（我们做的是"可操作的可视化"，不是录播）
- ❌ 不做社交/论坛/直播
- ❌ 不做自动生成题目、AI 判题（v1 不做，v2 可选）
- ❌ 不追求覆盖全部离散数学教材章节（先做到"少而精"）

## 2. 目标用户与典型场景

### 2.1 用户画像

| 画像 | 描述 | 核心诉求 | 占比预估 |
| --- | --- | --- | --- |
| **A. 课前预习的在校生** | 大一/大二，即将上离散数学或正在上，跟不上老师 | 上课前先"看懂"，降低课堂门槛 | 55% |
| **B. 补考的挣扎者** | 已挂科或濒临挂科，需要速成理解 | 抓重点、快、有即时反馈 | 20% |
| **C. 跨专业自学者** | 转码/考研/自学 CS，数学基础弱 | 从零开始，不能有任何"显然易得"的跳步 | 15% |
| **D. 教师/助教** | 想找演示素材用于课堂 | 可全屏播放、可暂停单步、可自定义输入 | 10% |

> **设计含义**：画像 C 决定了产品的下限——**任何一步都不能假设前置知识**。这是"傻子也能看懂"的具体来源。

### 2.2 典型使用场景

1. **地铁上 5 分钟**：手机竖屏，单手滑动，看一个"集合运算"小动画，点两下试试。
2. **图书馆电脑**：横屏大屏，打开"图论最短路径"，自己摆图、单步执行 Dijkstra，对照教材例题。
3. **课堂上投屏**：教师全屏打开"汉诺塔递推"，用方向键单步播放，学生跟着数步数。
4. **宿舍深夜复习**：笔记本 + 键盘，纯键盘操作完成"真值表"练习。

**结论**：同一份内容要同时支持 **触摸（拇指）/ 鼠标 / 键盘** 三种输入与 **竖屏窄宽 / 横屏宽屏** 两种布局，这是 §8 的技术约束起点。

## 3. 核心理念：如何定义"傻子也能看懂"

这是本项目最核心的设计约束。我们把它翻译成 **6 条可执行、可验收的规则**。

### 3.1 六条铁律

| # | 规则 | 具体要求（可验收） | 依据 |
| --- | --- | --- | --- |
| **R1** | **先看现象，后给符号** | 每个知识点必须先有 ≥1 个纯直觉动画（无任何公式），才允许出现第一个数学符号 | 具体→抽象 |
| **R2** | **一步一屏一件事** | 任一时刻屏幕上正在进行的变化不超过 1 处（高亮/移动/变色合计 1 个焦点）；同时出现的新概念 ≤ 1 个 | 认知负荷理论 |
| **R3** | **每个动作必有即时反馈** | 用户任何操作在 100ms 内产生可见反馈；错误反馈必须解释"为什么错"而不是只显示红叉 | 反馈闭环 |
| **R4** | **默认路径不依赖任何前置知识** | 从首页零跳转进入任一知识点，全程不需要外部资料；出现的每个新术语都在同屏有 1 句大白话解释 + 1 个悬停/点击可展开的正式定义 | 画像 C |
| **R5** | **用户必须动手，且动手是"必要"的** | 每个知识点至少 3 个交互环节，且**不操作就无法推进下一步**（不能只是"视频 + 一个播放按钮"） | 做中学 |
| **R6** | **允许失败，失败不惩罚** | 任何错误都可无限重试、可随时回退一步、可"看答案"后继续；无计时、无扣分、无失败弹窗 | 心理安全感 |

### 3.2 反面清单（写内容时的自查表）

以下写法一律打回重做：

- ❌ "显然可知…" "易证…" "由定义立得…"
- ❌ 一屏堆 3 个以上公式
- ❌ 动画只是"播放"，用户不能暂停/倒回/改变参数
- ❌ 用红色叉号 + "错误" 而不说明错在哪
- ❌ 一个新概念在同屏同时出现定义 + 例子 + 反例 + 定理
- ❌ 依赖用户"已经知道"某个更基础的概念（若确实依赖，必须先嵌入前置知识点的 30 秒迷你回顾）

### 3.3 三层语言策略

同一个概念在页面上以三种"语言"存在，用户可自由切换层次：

```
第 1 层【大白话】  "把两个圈里所有的东西倒在一起，就是并集"
第 2 层【图示】    Venn 图 + 元素被拖拽合并的动画
第 3 层【符号】    A ∪ B = { x | x ∈ A 或 x ∈ B }
```

默认从第 1 层进入，**第 3 层永远是可展开的、而不是默认显示的**。一个"显示正式定义"的开关贯穿全站。

### 3.4 分级提示（三级脚手架）

每个交互环节内置三级提示，逐级解锁，绝不一开始就剧透：

| 级别 | 触发方式 | 内容 |
| --- | --- | --- |
| H1 方向提示 | 用户停滞 15s 自动浮现 | "试试把左边那个点拖到圈里面" |
| H2 局部演示 | 用户点击「提示」 | 高亮正确目标区域 / 播放 2 秒局部示意动画 |
| H3 完整答案 | 用户再次点击「看答案」 | 自动完成这一步并解释原因，可一键回退重试 |

> 提示层级会被埋点记录，成为内容难度调优的核心数据（H2/H3 触发率高的环节 = 设计有问题）。

## 5. 每个知识点的标准教学结构（五步法）

所有知识点使用**同一套骨架**，这样开发可复用、用户有稳定预期、内容可批量生产。

### 5.1 五步骨架

| 步骤 | 名称 | 目的 | 时长占比 | 是否强制交互 | 示例（以"集合的并集"为例） |
| --- | --- | --- | --- | --- | --- |
| **① 钩子** | 生活场景引入 | 建立直觉，零符号 | 10% | 否（可点击触发动画） | 两筐水果倒进一个大筐 |
| **② 探索** | 自由玩耍 | 自己发现规律 | 30% | ✅ 强制 | 随意把小球拖进 A 圈/B 圈，观察大筐变化 |
| **③ 命名** | 给出概念与符号 | 把发现的东西"命名" | 15% | 轻交互 | 圆圈被命名 A、B，合并区域标为 A∪B，展示符号定义 |
| **④ 练习** | 引导式任务 | 在反馈中固化 | 30% | ✅ 强制（3–5 题） | "下列哪个元素属于 A∪B？"点击判定 |
| **⑤ 迁移** | 变换情境 | 验证是否真懂 | 15% | ✅ 强制（1–2 题） | 给三个集合求并；或问"并集一定比原来大吗？"（反例：A⊆B） |

### 5.2 页面布局（统一模板）

```
┌──────────────────────────────────────────────────────────┐
│ 面包屑 / 进度条 ①─②─③─④─⑤      [字幕] [语速] [显示正式定义] │  ← 顶部
├──────────────────────────────────────────────────────────┤
│                                                          │
│              【主舞台：动画 / 交互画布】                  │  ← 60% 高度
│                                                          │
├──────────────────────────────────────────────────────────┤
│  旁白/字幕条：一句大白话说明当前在干什么                    │  ← 常驻
├──────────────────────────────────────────────────────────┤
│  [上一步] [播放/暂停] [下一步] [重置]   ◀━●━━━▶ 速度      │  ← 控制条
└──────────────────────────────────────────────────────────┘
```

- **旁白条常驻**：任何时刻都有一句"人话"解释屏幕上正在发生什么（对应 R4）。
- **单步控制**：每一步动画都能暂停、前进、后退、重播（对应"用户主导节奏"，对抗线性视频）。
- **进度条 ①–⑤ 可视化**：用户随时知道"还有多少"，减少焦虑。

### 5.3 知识点内容 Schema（写作模板）

每个知识点必须填满以下字段，缺项不予进入开发：

```yaml
id: S2
title: 集合的运算
module: 集合与函数
prerequisites: [S1]           # 前置知识点（用于生成"30秒回顾"）
hook: 两筐水果倒进大筐       # ① 生活场景
bigIdea: 一句话本质
misconceptions:              # 典型误解（必须设计针对性反例动画）
  - "并集一定比原集合元素多"   # 反例：A ⊆ B
  - "交集为空就是没关系"
steps: [...]                 # 逐步动画脚本（分镜）
interactions: [...]          # 交互环节（含 H1/H2/H3 提示文案）
practice: [...]              # 练习题（含干扰项与错误解释）
transfer: [...]              # 迁移题
formalDefinition: "A ∪ B = { x | x ∈ A ∨ x ∈ B }"
glossary: [...]              # 本页新术语及其大白话解释
```

> 该 schema 直接对应 §10 的 MDX 组件契约，内容作者只需填 YAML，开发提供组件。

## 6. 交互动画与交互原语设计

**关键决策**：不每个知识点从零造轮子，而是先建 **8 个交互原语（Interaction Primitives）**，46 个知识点全部由原语组合而成。这是控制工期的核心手段。

### 6.1 交互原语库

| # | 原语 | 说明 | 复用到的知识点 | 难度 |
| --- | --- | --- | --- | --- |
| P1 | **集合画布 SetCanvas** | 可拖拽元素 + 若干可拖拽/缩放的圆形区域，实时计算 ⊆/∈/∩/∪ | S1–S3, S7, C3 | 中 |
| P2 | **图编辑器 GraphEditor** | 增删节点/边，拖拽定位，自动布局（力导向/层次），求度数 | G1–G8, T1, T2 | 高 |
| P3 | **矩阵编辑器 MatrixGrid** | 可点击切换 0/1 或数字的网格，与图形/表达式双向绑定 | R1, R2, R6, G1 | 中 |
| P4 | **表达式-电路-真值表联动三联体 LogicTriad** | 表达式 AST ↔ 门电路图 ↔ 真值表双向同步 | L1–L4, B1–B3 | 高 |
| P5 | **参数滑块与曲线 ParamLab** | 拖动 n/k 等参数，图表与计数结果实时重算 | C1–C6, S6 | 低 |
| P6 | **步骤播放器 Stepper** | 算法逐步执行/回退/自动播放，带状态快照（时间旅行） | G5, G6, R3, T2, T4, F1, F2 | 中 |
| P7 | **拖动排序/配对 DragMatch** | 拖拽元素到槽位、连线配对，带正确性校验 | S4, S5, L4, G8 | 低 |
| P8 | **游戏化画布 GameCanvas** | 带明确胜负/目标的手动玩法（一笔画、地图着色、汉诺塔） | G3, G4, G7, C5 | 中 |

> **工期影响**：若每个知识点单独开发，估算 3–5 人日/个；用原语组合后，MVP 阶段平均 **1–1.5 人日/个**，这是 12 周内交付 16 个知识点可行的前提。

### 6.2 动画设计规范

| 项目 | 规范 |
| --- | --- |
| 时长 | 单个动作 200–600ms；超过 800ms 必须可中断 |
| 缓动 | 统一使用 `cubic-bezier(0.4, 0, 0.2, 1)`；进出场不同缓动 |
| 物料 | 颜色 = 语义（见 §6.4）；禁止纯装饰性动画以防分散注意（R2） |
| 焦点 | 同一时刻只允许一处"运动 + 变色高亮"同时发生 |
| 过渡 | 状态变化必须"从旧位置长出来"，不能"瞬间替换"（保持对象恒常性，用户才不会迷路） |
| 可关闭 | 全局尊重 `prefers-reduced-motion`，降级为"淡入淡出 + 单步高亮" |
| 速度控制 | 全站 0.5× / 1× / 1.5× / 2× 可选，独立于系统动画设置 |

### 6.3 三种输入方式统一（关键架构决策）

把"用户意图"抽象成 **语义事件**，与具体输入设备解耦：

| 语义事件 | 触摸 | 鼠标 | 键盘 |
| --- | --- | --- | --- |
| `SELECT(target)` | 点按 | 左键单击 | `Tab` 聚焦 + `Enter` |
| `MOVE(target, to)` | 单指拖动 | 按住拖动 | 聚焦后方向键微调（每次 1 格，`Shift` 加速） |
| `CONNECT(a, b)` | 长按 A 再点 B | 从 A 拖到 B | A 聚焦 → `C` 键进入连线模式 → 选 B |
| `ADJUST(value)` | 拖动滑块 / 双指 | 拖动滑块 / 滚轮 | `←/→`，`Home/End` 到极值 |
| `STEP(±1)` | 底部按钮 | 按钮 / 滚轮 | `←/→` 或 `Space` 播放 |
| `UNDO / RESET` | 按钮 | 按钮 / `Ctrl+Z` | `Ctrl+Z` / 按钮 |

> **验收要求**：每个知识点页面必须能用**纯键盘**完成全部交互流程（§11 的 a11y 测试项）。这不是加分项，是交付门槛——因为它是"响应式多端"里最容易被忽略、也最难补做的一环。

### 6.4 色彩与视觉语义系统

| 语义 | 颜色 | 用途 |
| --- | --- | --- |
| 集合 A / 主体 | 蓝 `#3B82F6` | 第一组对象、默认高亮 |
| 集合 B / 客体 | 紫 `#8B5CF6` | 第二组对象 |
| 正确 / 已完成 | 绿 `#10B981` | 成功反馈 |
| 错误 / 冲突 | 橙红 `#F97316` | **错误提示不用纯红**，避免焦虑与色盲不可辨 |
| 新增 / 当前步骤 | 琥珀 `#F59E0B` | 算法当前正在处理的对象 |
| 已废弃 / 排除 | 灰 `#94A3B8` | 被淘汰的候选项 |

- 所有颜色对必须同时满足 **WCAG AA 对比度 ≥ 4.5:1**；
- 所有**颜色语义都附加图形/图案/文字冗余**（色盲用户必须能区分）——用形与纹，不只靠色。

## 7. 技术架构与技术选型

### 7.1 技术栈（推荐方案）

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | **Next.js 15（App Router）+ TypeScript** | SSG 保证首屏快、SEO 好；RSC 减轻客户端负担；生态成熟 |
| 样式 | **Tailwind CSS + shadcn/ui** | 原子化便于响应式；组件可复制进仓库，无黑盒依赖 |
| 状态 | **Zustand**（全局 UI/进度）+ **XState**（每个知识点的步骤机） | 步骤机天然表达"当前在第几步、允许哪些操作"，与 §5 五步法一一对应 |
| UI 动画 | **Motion（原 Framer Motion）** | 声明式、`layout` 动画强、内置 `prefers-reduced-motion` 支持 |
| 数学可视化 | **D3.js（只取 `d3-scale` / `d3-shape` / `d3-force` / `d3-hierarchy` 等子模块）** | 布局算法成熟（力导向、树、层次），避免自己实现图布局 |
| 渲染层 | **SVG 为主**；节点 > 300 时自动切 **Canvas 2D** | SVG 便于无障碍/事件绑定/样式；Canvas 保性能。**不用 WebGL**（过度设计） |
| 内容 | **MDX + 自定义组件** | 内容与引擎分离，作者可用 Markdown 写文案、用组件插入交互 |
| 代码高亮/公式 | **KaTeX**（非 MathJax） | 体积小、同步渲染、无闪烁 |
| 图形/几何工具 | `d3-force`, `graphlib`, `dagre`（层次布局）, `fraction.js`（精确分数） | 避免浮点误差导致"矩阵算错"的教学事故 |
| 后端（v1 极简） | **纯静态 + localStorage** 记录进度；可选 **Supabase**（Auth + Postgres）用于跨设备同步 | v1 不做账号也能用，降低门槛；需同步时再上后端 |
| 埋点 | **Plausible / Umami（自建）或 PostHog** | 需要细粒度交互事件（提示层级、卡点） |
| 部署 | **Vercel 或 Cloudflare Pages**；国内访问需备案域名 + 静态资源 CDN | 边缘分发、预览部署、一键回滚 |
| 测试 | Vitest + React Testing Library + **Playwright**（多视口 + 视觉回归） | 见 §11 |
| 工程 | pnpm + Turborepo（若拆包）+ ESLint + Prettier + Husky | 单仓即可，暂不拆微前端 |

### 7.2 动画方案选型对比（决策记录）

| 方案 | 优势 | 劣势 | 结论 |
| --- | --- | --- | --- |
| **SVG + Motion + D3** | 事件/无障碍/样式友好，可精确控制单步 | 节点极多时性能下降 | ✅ **主方案** |
| Canvas 2D | 性能好，适合大规模图 | 事件命中测试、无障碍需手写 | ✅ 备用（>300 节点自动切换） |
| PixiJS / WebGL | 极高性能 | 复杂度高、包体大、本项目不需要 | ❌ |
| D3 全量（含 transition） | 布局算法全 | D3 的 DOM 直操与 React 冲突 | ⚠️ 只用其**纯函数**布局模块，动画交给 Motion |
| Manim / 预渲染视频 | 效果好 | **不可交互**，违背核心需求 | ❌ 仅可用于"钩子"步骤的补充素材 |
| Lottie / Rive | 设计驱动、轻量 | 无法与数学状态双向绑定 | ⚠️ 仅装饰性场景 |

### 7.3 分层架构

```
┌─────────────────────────────────────────────────┐
│  内容层 (Content)   MDX 文件 + YAML 前注          │  ← 内容作者维护
├─────────────────────────────────────────────────┤
│  编排层 (Orchestration)  XState 步骤机 + 提示引擎  │  ← 复用，无知识点特化
├─────────────────────────────────────────────────┤
│  引擎层 (Engines)  16 个交互原语 + 动画规范        │  ← 复用，重点测试
├─────────────────────────────────────────────────┤
│  算法层 (Kernels)  纯函数：图算法/布尔化简/计数     │  ← 100% 单测覆盖
├─────────────────────────────────────────────────┤
│  平台层 (Platform) 响应式布局/输入抽象/a11y/埋点   │  ← 全站统一
└─────────────────────────────────────────────────┘
```

> **关键约束**：算法层必须是**零依赖 React 的纯 TypeScript 函数**，不做 DOM 操作。这样才能：
> ① 用单测穷举验证数学正确性（教学产品最不能容忍"算法错了"）；
> ② 同一份算法既能驱动动画，也能做"沙盒"自由输入；
> ③ 未来可复用到命令行工具或题库。

### 7.4 示例：算法层接口约定

```ts
// kernels/graph/shortestPath.ts —— 纯函数、可测试、与 UI 无关
export interface Step<S> { snapshot: S; explanation: string; highlight: string[] }

/** 返回完整的步骤序列，UI 只需按索引播放（天然支持单步/回退/时间旅行） */
export function dijkstra(graph: WeightedGraph, start: NodeId): Step<DijkstraState>[]
```

> **"返回步骤序列"而非"回调式执行"** 是整个交互设计的地基：因为它让"暂停/回退/跳到第 k 步"变得免费，而这正是"用户主导节奏"的技术前提。

## 8. 响应式与多端兼容方案

### 8.1 断点策略（按"内容形态"而非"设备"划分）

| 名称 | 宽度 | 布局模式 | 典型设备 |
| --- | --- | --- | --- |
| `xs` 手机竖屏 | < 480px | **上下堆叠**：舞台在上、控制条在下（拇指可达区） | 手机竖握 |
| `sm` 手机横屏 / 小平板 | 480–767px | 舞台放大，控制条转为悬浮胶囊 | 手机横握 |
| `md` 平板竖屏 | 768–1023px | 舞台 + 右侧抽屉式说明 | iPad 竖 |
| `lg` 桌面 | 1024–1439px | **左右分栏**：舞台 65% + 旁白/定义 35% | 笔记本 |
| `xl` 大屏/投屏 | ≥ 1440px | 分栏 + 可开启"课堂模式"（超大字号 + 隐藏导航） | 教室投影 |

> **不按"移动端/桌面端"两分**：因为手机横屏与平板竖屏的可用空间完全不同，两分布局必然有一端体验崩坏。

### 8.2 移动端竖屏优先原则

移动端是**下限约束**，必须最先设计：

- **单列垂直流**：舞台 → 旁白 → 操作提示 → 控制条（从上到下 = 从看到做）。
- **拇指热区**：所有可点控件的可点区域 ≥ 44×44 CSS px，主操作位于屏幕下 1/3。
- **手势冲突治理**：
  - 画布内拖动 = 操作对象，**禁用页面滚动**（`touch-action: none` 于画布内）；
  - 画布边缘/容器外 = 正常滚动；
  - 双指缩放仅在"图编辑器"中启用，其余页面禁止（防止误缩放打乱布局）；
  - 提供**明确的"退出画布"按钮**，避免用户被困（手势陷阱是移动端最常见的劝退点）。
- **横屏提示**：检测到 `G1`/`G5` 等宽画布知识点在竖屏下空间不足时，显示可关闭的"横屏体验更佳"轻提示，但**绝不阻断竖屏使用**。
- **性能降级**：低端机（依 `navigator.hardwareConcurrency` / 帧率探测）自动降级为：减少同时动画个数、关闭阴影/模糊、力导向迭代次数减半。

### 8.3 大屏与投屏支持

- "课堂模式"：字号 ×1.5、隐藏侧边信息、支持 `F` 全屏、方向键单步、`空格` 播放/暂停。
- 深色模式：全站支持，且**投影仪场景默认提供高对比度主题**（浅底 + 强对比，避免投影发灰看不清）。

### 8.4 浏览器与设备兼容矩阵

| 目标 | 版本 | 验证方式 |
| --- | --- | --- |
| Chrome / Edge | 最近 2 个大版本 | Playwright 自动跑 |
| Safari（macOS / iOS） | 最近 2 个大版本 | 真机 + BrowserStack |
| Firefox | 最近 2 个版本 | Playwright |
| Android Chrome | 中端机（骁龙 6 系同级） | 真机实测帧率 |
| iOS Safari | iPhone SE 尺寸（最小可用屏） | 真机实测 |

**最低支持基线**：`ES2020` + `ResizeObserver` + Pointer Events；不支持 IE 及任何无 Pointer Events 的环境（时代已终结，不做浪漫主义兼容）。

### 8.5 性能预算（硬指标，超出即阻断发布）

| 指标 | 预算 |
| --- | --- |
| 知识点页 JS 首包（gzip） | ≤ 180 KB |
| 全站首屏总资源（gzip） | ≤ 500 KB |
| 主舞台交互就绪（LCP/TTI） | ≤ 2.5s（4G 中端安卓） |
| 动画帧率 | ≥ 50fps（中端设备），无长任务 > 50ms |
| Lighthouse 性能 / 无障碍 | ≥ 90 / ≥ 95 |

### 8.6 无障碍（a11y）——同时也是"傻子也能看懂"的延伸

| 项 | 要求 |
| --- | --- |

| 认知无障碍 | 语言简单（目标：初中阅读水平）、一次一个概念、可无限重试 |

```
/about                  关于 / 教学理念 / 反馈入口
```

### 9.2 关键页面结构

**知识点页（`/learn/:topicId`）**

```
顶部：模块名 › 知识点名        ①─②─③─④─⑤ 进度     [Aa 字号] [动画:开/关]
─────────────────────────────────────────────────────────
主舞台（响应式，见 §8.1）
  └─ 画布 / 动画 / 交互区（含内嵌提示气泡）
─────────────────────────────────────────────────────────
旁白条：当前这一步在做什么（一句话）
[▸ 展开正式定义]  [▸ 展开术语解释]
─────────────────────────────────────────────────────────
控制条：⟨上一步⟩ ⟨播放/暂停⟩ ⟨下一步⟩ ⟨重置⟩   速度 ◀●▶
辅助：⟨提示 (H2)⟩ ⟨看答案 (H3)⟩ ⟨上一知识点 | 下一知识点⟩
─────────────────────────────────────────────────────────
底部：本页术语卡 · 相关知识点推荐 · "这一步没看懂？"反馈按钮
```

**"这一步没看懂？"按钮**：这是最重要的产品按钮。用户任意时刻可标记录音式反馈（"卡在第 3 步"），直接进入埋点，驱动内容迭代（§14）。它把"傻子也能看懂"变成可持续优化的闭环，而不是一句口号。

### 9.3 导航原则

- **零层级直达**：首页 → 任一知识点最多 2 次点击。
- **永不阻塞**：知识依赖只做"推荐顺序"，不做强制解锁（避免"我不知道从哪开始"的决策瘫痪，也避免被锁死的挫败）。
- **始终可见的"下一个"**：每页底部固定"下一知识点"按钮，把用户推着往前走。

## 11. 质量保障与教学有效性验证

> **核心观念**：这是一个教学产品，**"跑得起来"不等于"教得会"**。因此质量体系分两条腿：工程测试 + 教学验证。

### 11.1 工程测试策略

| 层级 | 工具 | 覆盖内容 | 目标 |
| --- | --- | --- | --- |
| 单元测试 | Vitest | 算法内核（图算法、布尔化简、计数、真值表） | **行覆盖 ≥ 95%**，含穷举小规模全量验证（如 n ≤ 5 的所有图性质） |
| 组件测试 | RTL | 交互原语的行为（拖拽后状态、键盘等价路径） | 每个原语 ≥ 8 个用例 |
| E2E | Playwright | 5 个视口 × 3 种输入（触摸模拟/鼠标/纯键盘）走完 MVP 全部知识点 | 每次 PR 全跑 |
| 视觉回归 | Playwright 截图 + 基线比对 | 关键帧（步骤 1/3/5）在三档视口 | 差异 > 0.1% 即报警 |
| 无障碍 | axe-core（CI） + 人工键盘走查 | WCAG 2.1 AA | 0 critical/serious 问题 |
| 性能 | Lighthouse CI + 自研帧率采样 | §8.5 全部预算 | 超标阻断合并 |
| 内容校验 | zod schema + 自定义规则 | §5.3 字段完整、文案反向清单（正则扫"显然""易证"） | CI 强制 |

**"算法正确性穷举"是本项目最关键的测试**：一根画错的边、一个错误的松弛顺序，会让学生形成错误认知，代价远高于一次崩溃。因此内核测试必须包含**与已知正确答案的交叉验证**（例如：Dijkstra 结果与 Floyd-Warshall 结果比对；卡诺图化简结果用真值表穷举验证）。

### 11.2 教学有效性验证（人因测试）

| 阶段 | 方法 | 样本 | 观测指标 |
| --- | --- | --- | --- |
| 原型期 | 纸面/低保真原型 + 出声思维（Think-Aloud） | 5 人（≥2 人非 CS 背景） | 卡点位置、困惑语句 |
| MVP 期 | 任务式可用性测试：给 5 个知识点，不讲解，只看 | 8 人（覆盖 §2.1 四类画像） | 无提示通关率、耗时、提示层级分布、SUS 量表 |
| 上线后 | 埋点分析 + "这一步没看懂"反馈聚类 | 全量 | 各步骤 H2/H3 触发率、跳出点分布 |
| 对比验证 | A/B：有动画 vs 纯文字版后测成绩 | 每知识点 n ≥ 60 | 后测正确率差值、延时测试（1 周后）保持率 |

**验收门槛（Go / No-Go）**：
- SUS ≥ 75；
- 非 CS 背景用户的无提示通关率 ≥ 50%（这是"傻子也能看懂"的硬门槛）；
- 每个知识点的后测正确率 ≥ 75%；
- 任一环节 H3（看答案）触发率 > 40% → 该环节必须重做。

### 11.3 专家与同伴评审

- **数学正确性评审**：每个知识点由 1 位数学/CS 专业教师复核（尤其术语、符号、定理表述）。
- **教学法评审**：教学设计负责人复核五步结构与误解清单。
- **文案评审**：内容编辑复核"无术语堆砌、无显然句式"。

## 14. 指标体系与迭代规划

### 14.1 埋点事件设计

| 事件 | 用途 |
| --- | --- |
| `topic_enter` / `topic_complete` | 漏斗起点与终点，算完成率 |
| `step_view`（含 stepId、停留时长） | 定位"哪一步让人卡住" |
| `interaction_attempt`（成功/失败、试错次数） | 评估交互难度是否合适 |
| `hint_trigger`（级别 H1/H2/H3） | **最核心的难度指标**：H3 率 > 40% 的环节必须重做 |
| `confused_click`（"这一步没看懂"） | 定性反馈聚类 |
| `navigate_next` | 知识链条的吸引力 |
| `reduced_motion_on` / `keyboard_only` | a11y 使用情况 |
| `device_profile`（视口、帧率、机型） | 定位性能问题设备 |

> **隐私原则**：只采集交互行为，不采集任何个人身份信息；首屏提供"不参与统计"选项；不使用第三方广告类追踪。

### 14.2 迭代循环（双周）

```
埋点数据 + "没看懂"反馈
      ↓  聚类出 Top 3 卡点
内容/交互改版（只改卡点，不重做）
      ↓
灰度 10% 用户，对比 H3 触发率与完成率
      ↓
达标则全量，否则回滚并重设计
```

### 14.3 路线图展望

| 版本 | 内容 | 备注 |
| --- | --- | --- |
| v1.0 | 30 个知识点 + 沙盒 + 进度 + 课堂模式 | 本文档交付范围 |
| v1.5 | 账号体系与跨设备同步、错题/卡点回访、教师布置任务 | 需后端 |
| v2.0 | 用户自定义输入的完整沙盒（任意图/任意布尔表达式）、分享链接（把当前配置编码进 URL） | 分享是自然增长点 |
| v2.5 | 导出为课堂演示包 / 嵌入 iframe 供教学平台使用 | 面向教师 |
| v3.0 | 生成式辅助：根据用户卡点自动生成变式练习与针对性动画 | 需谨慎，避免"AI 胡说数学" |

**"分享链接"值得提前设计**：让用户能把"我搭的这个图/这条路径"用 URL 分享出去，是低成本高回报的传播机制，所以 v1 的数据结构就应做到**状态可序列化**（这也正好是 Stepper 时间旅行所需的同一能力）。

| 组合计数 | 3 | 2 | 1 | P5, P8, P2 | 中 |
| 图论 | 5 | 1 | 3 | P2, P6, P8 | **高** |

> 图论与布尔代数是原语 P2/P4 的重度使用者，也是全项目最贵、最出彩的部分。**建议优先做它们，一是它们最具可视化价值，二是它们能验证原语是否真的足够通用。**

### 附录 B · 交互原语 API 草案（示例）

```ts
// 所有原语共享的统一契约：只吃 state，吐语义事件
export interface PrimitiveProps<S, A> {
  state: S;                          // 当前状态（由内核计算得出，原语不自己算）
  onAction: (action: A) => void;     // 用户意图（语义事件，与输入设备无关）
  stepIndex: number;                 // 用于单步高亮
  highlight?: HighlightSpec;         // 当前焦点对象
  a11y: { label: string; announce: (msg: string) => void };
  reducedMotion: boolean;
}

// 示例：图编辑器
export type GraphAction =
  | { type: 'ADD_NODE'; at: Point }
  | { type: 'REMOVE_NODE'; id: NodeId }
  | { type: 'TOGGLE_EDGE'; a: NodeId; b: NodeId }
  | { type: 'MOVE_NODE'; id: NodeId; to: Point };
```

**契约要点**：原语**不做数学计算**（计算属于内核）、**不做布局决策**（布局由内核给出坐标）、**不关心输入设备**（由平台层翻译）。这三条保证了原语可以被 46 个知识点安全复用。

## 结语

这份规划书把"**傻子也能看懂**"这句要求，拆成了 §3.1 的六条可验收铁律、§5 的五步统一骨架、以及 §11 的硬性数值门槛（非 CS 背景用户无提示通关率 ≥ 50%）。

项目的成败不在于做了多少个知识点，而在于两件事：

1. **原语能否复用**——它决定成本是线性爆炸还是可控增长；
2. **用户是否真的动了手**——不操作就不能推进，是"看懂"与"以为看懂"之间的分界线。

一句话总结技术哲学：**让算法返回"步骤序列"，而不是"最终答案"**。因为只要有了步骤序列，暂停、回退、单步、时间旅行、分享链接就全部免费——而这正是"交互式动画"相对一段视频的全部价值所在。
